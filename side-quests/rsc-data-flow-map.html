Architecture · one signal, one loop

The data flow is a circuit.

A web app is one program running on two computers — a server chip and a browser chip — joined by a single wire. Follow the signal: it descends the server, crosses the wire once as one HTTP response, climbs the browser to become interactive, then loops back across the top whenever a Server Action or navigation fires. The trace thickens with the client JavaScript it carries — hairline across the server (zero kb), heaviest at hydration. Tap any node to open the stage.

The whole flow, in one sentence.

Server

Render & serialize

Stages 1–4 run on the server: match the route, render Server Components, serialize the tree to Flight, and stream HTML from it. Your secrets and data-layer code stay here — they never ship.

Wire

One response

Stages 5–6 are the wire: Stream flushes HTML and the Flight payload together as one chunked HTTP response, and The Wire is that response in motion — interleaved bytes on a single persistent connection, with Suspense content arriving out of order and swapping into place. No second round trip.

Browser

Paint → hydrate

Stages 7–10 happen client-side: paint HTML for instant FCP, load client chunks, rebuild the tree from Flight, and hydrateRoot attaches listeners in place — interactive without re-rendering.
