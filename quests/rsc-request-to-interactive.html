What happens between
request and interactive

One request kicks off an ordered pipeline that crosses the network once: Server Components fetch data and render on the server, React serializes the tree into the Flight payload, react-dom streams HTML from it, the browser paints, then client chunks load and hydrateRoot wires up interactivity. This is a precise tour of every stage — server to browser, in execution order.

Server

Render & serialize

Stages 1–4 run on the server: match the route, render Server Components, serialize the tree to Flight, and stream HTML from it. Your secrets and data-layer code stay here — they never ship.

Wire

One response

Stage 5 streams HTML and the Flight payload together in a single HTTP response. Suspense boundaries flush a fallback first, then stream their resolved content in-band — no second round trip.

Browser

Paint → hydrate

Stages 6–9 happen client-side: paint HTML for instant FCP, load client chunks, rebuild the tree from Flight, and hydrateRoot attaches listeners in place — interactive without re-rendering.
