The anatomy of a Next.js request

A Next.js app is one program orchestrated across a build pipeline, a server runtime, and the browser. Node.js is the host process; React is the renderer; Next.js is the conductor that decides where code runs, when it runs, what gets cached, and what actually crosses the wire. 01 — THE STACK

Three regions. Two computers. One wire.

Next.js is one program that runs across two computers — a trusted server and an untrusted browser — joined by a single wire. A build region compiles your source once and ships 0 kb of itself. Node hosts. React renders. Next.js conducts.

The runtime runs your JavaScript and streams bytes; React turns a component tree into a stream; Next.js decides which tree, where, when, and how it reaches the browser.

NEXT.JS 16 · NODE RUNTIME · v0 — built from verified field notes

Node and Edge provide the execution environment; React provides the rendering model; SWC transforms individual files and Turbopack builds the dependency and chunk graphs; Next.js owns the conventions, routing, runtime decisions, cache rules, and the server/client boundary — and the browser receives the final negotiated result: HTML, RSC payloads, JS chunks, and streamed updates.
