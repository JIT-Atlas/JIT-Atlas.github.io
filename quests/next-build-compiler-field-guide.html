01 — pipeline

From source files to a deployable runtime.

A Next.js build starts with your project files, but it does not simply concatenate them. It reads configuration, resolves environment variables, classifies modules into runtime graphs, compiles TypeScript and JSX, processes assets, splits server and client boundaries, builds chunks, analyzes routes, prerenders what can be static, writes manifests, and finally reports what was produced.

02 — graph analysis

  
The app becomes several graphs, not one bundle.

  
Next.js and Turbopack have to decide which modules belong to the server runtime, which belong to the browser runtime, which are route handlers, which are assets, and which files are only metadata. The split matters because each graph has a different runtime and a different failure mode.

03 — App Router DSL

  
Your folder tree is a routing language.

  
In the App Router, the tree is not just organization. Folder names are path grammar. Special files are framework keywords. Nesting is layout composition. Dynamic folders are parameters. Route groups are invisible organization. Next.js reads that structure and emits internal route manifests from it.

04 — RSC transport

  
Initial load can stream HTML and Flight together. Client navigation usually asks for Flight separately.

  
The browser can paint HTML immediately, but React also needs the serialized Server Component tree so it can reconcile what the server rendered and hydrate Client Component boundaries. That serialized tree is the Flight / RSC payload.

05 — manifests

  
A manifest is a map for a later reader.

  
The word “manifest” causes confusion because there are two very different categories. Your app/manifest.* is browser-facing metadata for installability and icons. Internal .next/ manifests are build products that Next, React, the router, the deployment adapter, or the cache system read later.

06 — .next output

  
The build output is a directory of runtime artifacts.

  
.next/ is not just “the bundle.” It contains server-side bundles, browser chunks, static assets, generated HTML/RSC artifacts, route metadata, cache data, and traces that explain which files a deployment needs to copy.

07 — handbook

  
The deeper rule: every artifact exists because something later needs to read it.

  
Lock this in: the tree is the config, the filenames are the keywords, the graphs decide runtime ownership, and the manifests are the maps that let runtime readers find the correct thing later.

  
tap any concept to expand ↗

  

    
Initialization / configLoads project-level rules before the graph is trusted: Next config, TypeScript config, compiler options, output mode, experimental flags, redirects, image settings and environment conventions.

    
Env inliningBrowser-safe public values can be replaced in client bundles. Server-only values must remain server-only and must not leak into client chunks.

    
Tree shaking / DCEDead code elimination removes unreachable exports and branches after the graph and transforms make dependencies explicit enough to prove what is unused.

    
Chunking / prefetchThe client graph is sliced into route-aware chunks so navigation can fetch likely-needed code without shipping the whole app on first paint.

    
MinificationProduction code is made smaller after semantic transforms. The goal is less transfer and less parse work, without changing runtime meaning.

    
Reporting / budgetingThe final stage is feedback: route sizes, chunk relationships, slow prerenders, oversized assets and accidental client bundle growth.

  





  

    

      
Every artifact has a reader.

      
The build emits nothing for its own sake. Each file — chunk, manifest, payload or trace — exists because a later runtime, router, browser or deploy step needs to read it.

    

    
NEXT.JS 16 · BUILD PIPELINE · TURBOPACK — field notes

  

  
During development you split code for human understanding; during the build Turbopack follows the dependency graph and reshapes that code for machines — deciding where each module runs, when it runs, what crosses the network boundary, and writing the manifests and traces that let every later reader find the right thing.
