01 The mental model

JavaScript describes what. The browser decides how.

Everything below is a consequence of one split. fetch() does not send bytes — it hands the browser a description of a request, returns a Promise immediately, and lets the engine do the real work on the far side of a hard boundary. The Web platform reuses this exact shape everywhere:

the recurring pattern a JS wrapper is created early  →  the engine does the real work  →  a JS wrapper is injected back later. 
DOM     document.createElement() → JS wrapper → C++ DOM node
Events  addEventListener()       → JS wrapper → C++ dispatch
Timers  setTimeout()             → JS handle  → OS timer
Fetch   fetch()                  → JS Request → C++ network stack

04 The process model · where the request physically lives

Your fetch leaves the renderer process entirely.

The biggest thing the simple “JS → C++” story hides: a fetch crosses three operating-system processes, connected by mojo IPC pipes. The renderer is sandboxed and owns no sockets. The browser process is the privileged broker. The actual networking — and, critically, the CORS enforcement — happens in a separate network service process. Click any box for the classes involved.

⬡ Renderer · Browser · Network service
the security punchline CORS is enforced in the network service, not the renderer — because under Site Isolation a compromised renderer must not be trusted to police its own cross-origin reads.

06 CORS & preflight

The browser's veto — fired before a single byte of your request leaves.

Preflight guards against credential leakage, cross-site request forgery, and silent privilege escalation. Because Authorization is non-simple, the engine must ask permission first. Click a node to expand the gate.

07 Return path

Bytes become a Response, then a Promise resolution, then a value.

Five frames bring the response home. Notice the Response is born before the body finishes downloading — the body is a stream fed across a mojo data pipe.

08 The two-stage await

One promise for the headers, another for the body.

lock this in fetch() resolves when the browser can build a Response — usually once response headers arrive. It does not mean the body has downloaded. 
const response = await fetch(url);      // 1) waits for headers + Response shell
const data     = await response.json();  // 2) waits for the body stream to drain & parse

The first await gets the metadata shell — status and headers. The second drains and parses the body stream. A slow body, a hung connection, or a manual response.body read all live in stage two; the Response object already exists by then.

09 What JS can read

CORS controls visibility, not just sending.

After a cross-origin response, the engine filters what response.headers will expose. This is also why DevTools ≠ JavaScript: DevTools reads the network-service state; your code reads a filtered wrapper view.
